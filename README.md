# Nebula Mail — AI-Powered Mail Web Application

An AI-native, live Gmail web application featuring natural language assistant control, real-time push synchronization via Google Cloud Pub/Sub and Server-Sent Events (SSE), and a modern React frontend interface.

---

## 1. Overview

**Nebula Mail** connects directly to Google's Gmail API via OAuth 2.0 to provide a complete web mail application. Beyond standard email management (Inbox, Sent, Drafts, Search, Compose, Reply, Forward), Nebula Mail includes an integrated **AI Assistant** powered by OpenRouter function/tool calling.

Unlike chat widgets that merely output text, the Nebula Mail AI assistant understands the state of the UI and controls the application through structured tool execution. Users can prompt the assistant in natural language to search messages, open specific emails, navigate by list position, generate summaries, and prepare replies or drafts.

## 2. Implemented Features

- **Google OAuth 2.0 Authentication**: Official Google login with persistent SQLite token storage (`oauth_tokens`) allowing seamless session persistence across server restarts.
- **Live Gmail Data**: Real-time listing of Inbox, Sent, and Drafts emails fetched directly from the Gmail API.
- **Manual Email Management**: Full support for compose, send, reply, forward, category tabs (Primary, Promotions, Social, Updates), search, pagination, and unread counts.
- **Gmail Threading / Conversation View**: Multi-message thread loading, thread header formatting, reply history hierarchy, and conversation history parsing.
- **Sandboxed HTML Email Rendering**: Email bodies render inside an isolated, sandboxed `iframe` (`srcdoc` with `sandbox="allow-popups allow-popups-to-escape-sandbox allow-same-origin"`) to safely display raw HTML, embedded inline styles, and external images while preserving visual formatting.
- **Natural Language AI Compose**: AI generates subject lines and email bodies based on user intent and populates the compose form with a character-by-character typing animation.
- **Mandatory Human Send Confirmation**: Any email send operation generated by the AI requires explicit user review and confirmation before the email is dispatched through Gmail.
- **Main UI Search Integration**: Natural language queries (e.g., *"Show unread emails from the last 3 days"*) update the primary UI list view directly using Gmail search syntax (`is:unread newer_than:3d`).
- **Context-Aware AI Assistant**: On every interaction, the assistant receives full context of the active view, currently displayed email (including clean readable text body), and top displayed list metadata.
- **Single-Turn Multi-Step AI Actions**: The assistant can perform multi-action sequences in a single turn (e.g., *"Open the 6th email in the inbox and summarize it"* or *"Open the latest Naukri email and reply saying thank you"*).
- **Positional Email Navigation**: Ability to open emails by 1-indexed position in the currently displayed UI list (`openEmailByPosition`).
- **Real-Time Push Sync**: Near-instant inbox updates via Google Cloud Pub/Sub push webhooks routed to the frontend using Server-Sent Events (`SSE`).
- **Dark & Light Mode Themes**: Full theme system with CSS variables and custom properties.
- **Automated Unit Tests**: Backend test suite covering MIME extraction, HTML tag stripping, positional navigation, context isolation, structured tool returns, and OpenAI function message formatting.

## 3. System Architecture

### Core Execution Flow

```text
User Input (Chat / UI)
  ↓
React Frontend (App.jsx)
  ↓
Express Backend (/api/assistant)
  ↓
OpenRouter API (LLM Model)
  ↓
Structured Tool Call Response
  ↓
Assistant Action Registry (assistantActions.js)
  ↓
React State / Main UI Update
  ↓
Gmail API (google.gmail.v1)
```

### Real-Time Push Sync Flow

```text
Incoming Email in User's Inbox
  ↓
Gmail Infrastructure
  ↓
Google Cloud Pub/Sub Topic & Push Subscription
  ↓
Express Webhook Endpoint (/api/gmail/webhook)
  ↓
Server-Sent Events Broadcast (/api/events)
  ↓
React Frontend SSE Listener (EventSource)
  ↓
Silent Inbox & Unread Count Refresh
```

## 4. AI Assistant Architecture

The AI assistant operates via structured function calling rather than direct DOM manipulation.

1. **Context Injection**: On every request to `/api/assistant`, the client sends `messages` along with `actionRegistry.getCurrentContext()`. This includes `currentView`, `currentEmailId`, `currentEmail` (with clean readable body text), and `currentEmailList` (position, sender, subject, date of top 20 items).
2. **OpenRouter Function Calling**: The backend formats the system prompt and registers available tool definitions (`tools` array). OpenRouter returns structured `tool_call` JSON payloads when action execution is required.
3. **Action Registry Pattern**: The frontend `ActionRegistry` (`assistantActions.js`) maintains registered UI actions. Executing an action (e.g. `openLatestEmail`) updates React state (`currentEmail`, `currentView`) and returns a structured result containing full email details.
4. **Controlled Multi-Step Loop**: `handleAssistantSend` runs a `while` loop (capped at a maximum of 5 iterations). When a tool is executed:
   - The assistant tool call message (`role: "assistant"`, `tool_calls: [...]`) is appended to history.
   - The tool result message (`role: "tool"`, `tool_call_id`, `content: JSON.stringify(result)`) is appended.
   - The updated message history and fresh UI context are posted back to `/api/assistant` to receive the follow-up text answer or next tool call in the sequence.
5. **No Direct DOM Mutation**: The LLM NEVER directly manipulates the DOM. It emits structured intent parameters which are safely validated and executed by the application's action registry.

## 5. AI Tool Specifications

The application implements the following 13 tool and context definitions:

| Tool Name | Parameters | Purpose & UI Action |
| :--- | :--- | :--- |
| `openInbox` | *None* | Navigates the main UI to the Inbox list view. |
| `openSent` | *None* | Navigates the main UI to the Sent list view. |
| `openDrafts` | *None* | Navigates the main UI to the Drafts list view. |
| `openCompose` | *None* | Opens the email compose modal view. |
| `openEmail` | `emailId` (string) | Opens a specific email in Detail view by its Gmail ID. |
| `openLatestEmail` | `query` (string) | Searches Gmail for matching query and immediately opens the single most recent matching message in Detail view. Returns full email details (`id`, `from`, `to`, `subject`, `date`, `body`). |
| `openEmailByPosition` | `position` (integer) | Opens an email by its 1-indexed position in the currently displayed UI list (1 = 1st email, 6 = 6th email). Returns full email details. |
| `searchEmails` | `query` (string) | Searches Gmail using query syntax (`from:sarah`, `is:unread`, `newer_than:7d`) and updates the **main UI list**. |
| `fillCompose` | `to`, `subject`, `body` | Opens compose view and populates recipient, subject, and body with character-by-character typing animation. |
| `sendEmail` | `to`, `subject`, `body` | Prepares draft for sending and triggers mandatory human confirmation prompt (`pendingConfirmation: true`). |
| `replyToEmail` | `replyBody` (string) | Populates a reply draft for the currently open email with recipient `Re: <subject>` and sets pending send state. |
| `forwardEmail` | `to` (string), `extraNote` | Populates a forward draft for the currently open email with forwarded headers and original message content. |
| `getCurrentContext` | *Getter function* | Returns active UI view, current email object, and displayed email list metadata. |

## 6. Safety & Human Confirmation Gate

Nebula Mail enforces a strict **Human-in-the-Loop** safety policy:

- The LLM **cannot** silently send an email.
- When an AI command requests sending an email or replying/forwarding, the action handler populates the draft, sets `pendingSend = true`, and returns `pendingConfirmation: true`.
- The UI presents an explicit confirmation prompt (*"Your email is ready to review. Would you like me to send it?"*).
- The actual Gmail API call (`gmail.users.messages.send`) is executed **only** when the user manually clicks the **"Confirm Send"** button in the UI.

## 7. Gmail OAuth 2.0 Setup Guide

1. **Google Cloud Console Configuration**:
   - Go to [Google Cloud Console](https://console.cloud.google.com/).
   - Create a new project named `Nebula Mail`.
   - Navigate to **APIs & Services > Library** and enable **Gmail API**.
   - Navigate to **APIs & Services > OAuth consent screen**:
     - Choose **External** user type.
     - Set App Name to `Nebula Mail`.
     - Add your developer email.
     - Under **Test Users**, add your Gmail email address.
   - Navigate to **APIs & Services > Credentials**:
     - Click **Create Credentials > OAuth client ID**.
     - Select **Web Application**.
     - Authorized JavaScript origins: `http://localhost:5000`, `http://localhost:5173`
     - Authorized redirect URIs: `http://localhost:5000/auth/google/callback`
2. **Backend Configuration**:
   - Copy `.env.example` to `backend/.env`.
   - Fill in your `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.
3. **Authorization Flow**:
   - Start the backend server (`node backend/server.js`).
   - Open `http://localhost:5000/auth/google` in your browser.
   - Sign in with your test Gmail account and grant permissions.
   - Tokens will be saved automatically to `backend/db/nebula_mail.db` (`oauth_tokens` table).

## 8. Real-Time Push Sync Setup (Google Cloud Pub/Sub)

To enable automatic real-time inbox synchronization without manual refreshing:

1. **Create GCP Pub/Sub Topic**:
   - In Google Cloud Console, navigate to **Pub/Sub > Topics**.
   - Create a topic named `nebula-mail-topic`.
   - Under Topic Permissions, grant role **Pub/Sub Publisher** to `gmail-api-push@system.gserviceaccount.com`.
2. **Create Push Subscription**:
   - Create a subscription for `nebula-mail-topic`.
   - Delivery type: **Push**.
   - Endpoint URL: `https://<your-domain-or-ngrok>/api/gmail/webhook`.
3. **Local Development Tunnel (ngrok)**:
   - Run ngrok to expose port 5000:
     ```bash
     ngrok http 5000
     ```
   - Update your Pub/Sub subscription endpoint URL to `https://<your-ngrok-id>.ngrok-free.app/api/gmail/webhook`.
4. **Backend Webhook Handling**:
   - The backend `/api/gmail/webhook` endpoint receives push notifications, decodes incoming message payloads, and broadcasts events over Server-Sent Events (`/api/events`).
   - The React frontend listens via `EventSource` and silently refreshes the inbox list.

## 15. Engineering Tradeoffs

1. **Gmail API vs. Custom IMAP/SMTP Server**: Using the official Google Gmail REST API provides native OAuth security, rich query capabilities, and push notifications, but requires Google Cloud project setup and token management.
2. **OpenRouter for LLM Orchestration**: Allows switching between models (e.g. `openrouter/free`, `anthropic/claude-3.5-sonnet`, `openai/gpt-4o`) without changing application logic.
3. **SQLite Token Persistence**: `better-sqlite3` provides lightweight, single-file zero-config persistence for OAuth tokens without requiring an external database server.
4. **Server-Sent Events (`SSE`) vs. WebSockets**: SSE was chosen for real-time notifications because data flow is strictly unidirectional (backend push events to client), avoiding WebSocket connection overhead.
5. **Sandboxed `iframe` HTML Email Rendering**: Renders full responsive HTML emails safely without style pollution into the main application DOM.
